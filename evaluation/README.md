## 2026-10-06 多服务评测

评测支持指定部署服务，在线调用必须同时提供 `--answers`、`--service` 和 `--allow-model-send`。服务缺失、密钥缺失或未明确允许发送时，在初始化向量模型和发起请求之前停止。默认仍只检索。

```bash
# 不调用回答模型；生成 JSON 和可读报告
python evaluation/run.py --mode keyword --output evaluation/new-retrieval.json --markdown-output evaluation/new-retrieval.md

# 在线模式，需要真实服务配置，会产生 API 费用
python evaluation/run.py --mode keyword --answers --service tencent --allow-model-send --output evaluation/new-answers.json --markdown-output evaluation/new-answers.md
```

新报告区分以下口径：

- `retrieval_all_evidence`：预设证据是否全部进入前三。追问使用数据集的独立问题，不能代表模型改写质量。
- `criterion_pass`：原有状态和事实字符串检查；不是语义准确率。
- `citation_check`：`answered` 为结构、来源编号和摘句检查通过；`unverified` 表示未核验，可能源于格式或引用问题；资料不足和服务错误为不适用。
- `call_count` / `successful_calls`：实际请求次数和收到有效正文次数。请求成功不代表答案正确。多轮题包括前置回答、改写和最终回答。
- `answer_seconds`：整个题目流程耗时，包含前置调用和检索；调用元数据中的耗时则是单次 HTTP 请求和响应处理。
- `reported_tokens` / `token_reporting_coverage`：只累加服务实际返回的非负整数，逐字段记录覆盖调用数；全无数据时为 null。不是总成本，也不能在覆盖不完整时当作完整用量。

结果同时记录服务配置指纹和数据集 SHA-256。对照应保持题目集合、检索方式、代码版本和发送设置一致，重复多次并人工核对适用条件、错误解释与遗漏。JSON 包含评测问题、答案和服务地址，可读 Markdown 不复制答案正文，但仍包含服务配置元数据。

本次新增 8 项离线测试，总计 83 项通过（77 项功能与评测测试、独立运行的 6 项向量测试）。使用模拟服务响应验证两服务路由、显式发送许可、失败区分、多轮调用归属和用量统计；没有在线模型效果对照。

本地重新运行原 20 题关键词检索，全部指定证据进入前三为 13/14，与历史结果一致。新记录为 [JSON](keyword-retrieval-2026-10-06.json) 和 [可读报告](keyword-retrieval-2026-10-06.md)。没有覆盖或重跑历史 hy3 在线答案记录。

## 新合成挑战集与对照工具

新增 `challenge_cases.json`，共 20 题，14 道有答案、6 道缺失或冲突题，使用合成差旅、采购、支持和约 4 千字运营资料。覆盖数值边界、适用条件、例外、否定、长文跨段、多轮与不可信文档指令。没有据此修改 RAG 提示词、检索或引用算法；已经做检索诊断，因此不能称作盲测或真实用户独立基准。人工审题时修正“能否承诺一小时解决”的标签：应允许基于资料解释不能承诺，而非一律要求拒答。最终数据集指纹见报告。

关键词检索在 14 道有答案题中有 13 道的指定证据全部进入前三。`long_multi_conditions` 未覆盖所有材料、期限与续借条件，说明现有 Top-3 检索对分散证据存在边界。原始 [JSON](challenge-keyword-2026-10-06.json) 与 [可读报告](challenge-keyword-2026-10-06.md) 保留结果，不调整算法以刷分。

新评测通过 `--dataset evaluation/challenge_cases.json` 选择数据集；载入前检查唯一题号、证据是否存在、题目和事实检查字段。`forbidden_facts` 可拒绝包含预设错误说法的答案，但字符串检查仍无法完整判断语义。每题人工检查要点与 [待填写复核表](challenge-human-review.md) 一并提供。

`compare.py` 只读取两份已有在线报告，拒绝数据集指纹、实现代码指纹、检索方式、题目顺序不同的对照，也拒绝把同一服务配置当双模型。它生成单次对照，不执行模型请求或统计显著性判断。旧报告缺少这些字段时需重新运行，不能冒充严格可比。报告代码指纹覆盖问答、文档、检索、向量、引用验证、模型服务和评测程序。

累计 89 项离线测试通过（83 项功能与评测、6 项向量索引）。新增 6 项测试覆盖数据集校验、指定数据集零模型请求、错误说法检查以及不可比报告拒绝。DeepSeek 配置已准备但密钥未配置，没有在线结果；用户任务测试计划在 `docs/user-study.md`，没有用户反馈或效率提升结论。

新增可选条件核对、三/六处证据预算、拒答类别与逐次发送预览。`expanded-retrieval-2026-10-07` 显示原 20 题挑战集全指定证据覆盖 14/14；这是开发回归数据，不是独立长文效果。

修正版原始报告曾把条件拦截归入引用失败。`reporting-corrected/` 的派生报告保留原始报告 SHA-256、原代码指纹和修正说明，只修报告类别，不修改原答案或预设分数。核对通过是模型判断，被拦截不是任务成功。见 [流程与复核说明](../docs/trust-workflow.md)。
