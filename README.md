# 知页 · AI 知识库助手

上传 PDF、Word 或 TXT，检索原文片段，再由腾讯 MaaS 模型生成带段落引用的回答。

侧栏提供虚构员工手册示例，无需准备文件即可体验。页面展示已读取字数、问答轮次、实际耗时和引用原文；处理过程中显示理解问题、检索、生成和引用检查的实际步骤。单个文件限制 20 MB。

## 本地运行

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

在本地 `.env` 配置 `TENCENT_API_KEY` 和 `TENCENT_API_BASE_URL`。密钥不要提交到 Git。Streamlit Cloud 使用 Secrets 配置同名变量。

## 两种检索方式

- **关键词检索**：BM25 排序，中文使用相邻双字匹配。无需下载向量模型，但对同义改写支持有限。
- **语义检索**：本地 BGE-small-zh-v1.5 生成向量，Chroma 按余弦距离检索。侧栏可切换；首次使用需要联网下载模型到 `.model_cache/`。

模型权重可跨会话复用，文档索引由各会话独立持有。同一文档重复提问复用向量，切换文档替换旧索引。侧栏可清除文档索引。索引在内存中，不跨应用重启保存。向量计算在应用运行的机器上完成，选中的原文和问题仍会发送给腾讯 MaaS 生成回答。

语义相似度只是排序依据，不代表答案准确率。语义检索会返回最接近的候选片段，不使用未经校准的相似度阈值判断有无答案。模型必须声明资料是否足够，并为每条结论返回来源编号和连续原文摘句。程序检查格式、编号和摘句，失败时不展示拟生成的答案。分块上限为 400 字符，尽量保留完整段落，长段落优先按句子拆分，相邻块最多重叠 60 字符（为容纳完整段落可能减少）；超过模型 token 上限的输入会报错而不会静默截断。当前支持结合最近三轮有效问答理解追问；历史答案只用于补全问题，不作为回答证据。

## 连续问答与保存

每个浏览器会话独立保存当前文档的解析结果、问题、回答、状态、耗时和来源。切换检索方式、清除索引或展开来源不会重新生成或丢失已有回答；同一文件不会每轮重复解析。文件名与文件内容共同计算标识。有历史问答时，更换、修改或移除文档需要点击“确认切换文档”，确认前保留原记录并暂停提问，允许先导出。确认后清空旧对话与索引，损坏的新文件不会继续沿用旧文档。清空对话也需要先勾选确认。

追问会先调用模型补全为独立问题，再检索当前文档。页面显示改写后的问题，便于发现指代理解错误。普通首轮最多一次回答请求；有有效历史的后续问题通常增加一次改写请求，因此可能增加费用和等待时间。

记录存在服务器的当前会话内存中，不是永久保存。浏览器刷新、断开或服务重启可能丢失。可导出 Markdown（含问题、回答、状态及引用原文）；更换文档前请先导出。当前不支持导入记录或跨设备同步。

## 无答案与错误状态

- `answered`：模型声明可回答，且引用编号与原文摘句通过检查。
- `no_match`：关键词没有匹配，跳过回答请求。
- `insufficient`：候选原文不足以回答；候选内容可查看，但不显示成已引用证据。
- `unverified`：格式错误、来源编号无效或原文摘句核验失败；不展示未经核验的拟回答。
- `error`：服务或追问解析失败；记录保留，界面操作不会自动重复请求。

回答模型仍为腾讯 `hy3`。调用明确设置 `thinking.type=disabled`，保留 1,500 输出 token 上限，适合当前简短文档问答。返回正文为空或 `finish_reason=length` 时报告服务错误，不将其误判为文档无答案。追问只补全主题与指代；身份不明时允许说明带适用条件的政策，不假定用户符合条件。

这些检查不是完整的事实核验：一条真实摘句仍可能被模型错误解释，也可能遗漏条件或错误拒答。尚未用独立数据集测量拒答准确率，不能保证消除幻觉。

## 原文引用

回答提示使用 `[来源1]` 等编号，页面展示同编号的原文、文件名与位置。PDF 从读取时保留物理页码（从文件第一页开始计数，可能与印刷页码不同）；跨页片段列出所有实际涉及页面。Word 显示正文段落或表格行位置，TXT 以空行划分段落。重复的相同片段合并来源位置。

不满 100 字的短文档也可以提问。PDF 中未提取到文字的页面会提示，不会悄悄当作已读取；暂不支持扫描图片 OCR。复杂 PDF 多栏、表格的阅读顺序仍可能不准确。Word 当前只读取正文段落及顶层表格，不包含页眉页脚、批注和文本框。分块尽量保留结构，但不能保证规则与所有例外都处于同一片段；引用位置可追溯也不等于模型结论已经经过事实核验。

## 文件结构

- `app.py`：界面与会话状态。
- `rag_core.py`：追问补全、检索和回答流程。
- `conversation.py`：文档会话、结果保存和导出。
- `grounding.py`：回答状态、结构化输出与原文摘句检查。
- `documents.py`：文件读取、原文位置与分块。
- `retrieval.py`：关键词检索。
- `vector_retrieval.py`：本地向量模型及文档索引。
- `test_documents.py`、`test_retrieval.py`、`test_vector_retrieval.py`、`test_conversation.py`：自动测试，包含界面状态验证。
- `evaluate_retrieval.py`：六条虚构员工政策的检索对照实验。

## 验证

```bash
python -m unittest discover -v
```

自动测试不调用付费 API。向量单元测试使用预设向量检查索引、排序、缓存和隔离；它们不衡量真实模型的语义准确率。

直接依赖版本固定在 `requirements.txt`，本轮在 Python 3.14.7 的本地环境验证；这不是包含全部间接依赖的锁文件，也未验证云端部署。

## 20 题开发评测

`evaluation/cases.json` 覆盖直接提问、同义改写、多轮追问、多项条件、资料缺失和资料冲突。默认只评估检索；显式添加 `--answers` 才调用已配置的在线回答服务并产生用量。

```bash
python evaluation/run.py --mode keyword --output evaluation/keyword-retrieval.json
python evaluation/run.py --mode semantic --answers --output evaluation/semantic-answers.json
```

每次完整回答评测最多 24 次请求，包括两道追问的前置问答及改写。事实要点采用字符串检查，需要人工复核；这批题参与了调试，不能作为独立准确率或泛化能力证明。历史报告与结果解释见 `evaluation/README.md`。

## 小范围检索对照

运行 `python evaluate_retrieval.py`，只计算向量，不调用回答 API。模型缓存齐全时可设置 `HF_HUB_OFFLINE=1` 离线运行。

2026-09-07 的六条改写问题测试：

| 指标 | 关键词检索 | 语义检索 |
| --- | --- | --- |
| 正确段落排第一 | 2/6 | 4/6 |
| 正确段落进入前三 | 2/6 | 6/6 |

这只是开发过程中使用的小样本，不是独立评测集，也不是最终回答准确率。“多久转正”和“进修资金”两题的正确段落排第二，说明排序仍有改进空间。问题使用模型官方建议的检索提示语，原文不添加提示语。
