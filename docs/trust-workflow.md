# 回答核对、证据范围与发送预览

## 用户问题与产品取舍

用户需要的不只是一个有出处的句子，还需要知道能否办理、要经过谁批准、需要什么材料。此前实测发现：答案摘句真实，结论仍会漏掉批准条件；长文中的材料和期限分散在不同片段，取前三处会漏证据。本轮针对这些已观察到的问题改动，没有宣称已验证企业市场需求。

### 1. 有限扩展候选证据

界面默认开启“补充长文证据”，最多取六处；取消后回到原来的三处。继续使用现有 BM25 或向量排序，没有添加额外搜索或自动模型改写轮次，也不做无限相邻段落拼接。单处最多约四百字符，因此文本预算有限。

20 题挑战集仅检索评测中，全部指定证据覆盖从原模式 13/14 到补充模式 14/14。此集参与开发，不是盲测；这不证明任意长文都能覆盖，也不能把多取片段的收益包装成新检索算法。更多证据会增加输入费用、延迟与干扰内容，语义模式的长文效果尚未进行新的在线评测。

### 2. 可选条件模型核对

用户可开启“回答后核对关键条件”，默认关闭。只有通过原有格式、来源编号和连续摘句验证的回答才进入核对；无匹配、资料不足、原引用验证失败不会额外核对。

核对请求发送到同一个已确认服务，包含本轮问题、生成的结论与本轮候选原文，不引入其他提供方。核对模型只检查当前操作直接相关的资格、审批、材料、期限、例外与禁止事项。核对 JSON 严格检查布尔值、问题列表、来源编号和连续摘句；发现问题时隐藏拟回答，展示核对提示和带位置的原文。核对格式或摘句不合法时也不展示为可靠答案。核对服务调用失败时显示服务错误，不跳过核对展示答案。

这增加一次调用，不自动修补或重试。相同模型可能与生成模型共享盲点，核对通过不是独立语义证明；既可能漏判，也可能误报。重要操作仍应核对制度原文或咨询负责人。

回答引用编号会按已使用来源重新排列；核对请求去除答案内的展示编号，只按候选原文编号定位问题，避免两套编号误导核对。

### 3. 拒答有下一步

模型可给出限定的拒答类别：缺规则、缺个人条件、规则冲突、候选证据不全。程序只接受白名单类别，显示本地固定说明与操作建议，不直接展示模型自行编造的拒答理由。类别是模型判断，不证明整份文档缺失答案。

无匹配建议使用原文关键词；证据不全建议补充模式或分开提问；个人条件不足建议补充必要条件但避免无关敏感信息；冲突建议核对生效顺序和咨询负责人。服务错误仍独立显示，不冒充无答案。

### 4. 逐次发送预览

“每次发送前查看内容”默认关闭，用户可按需要开启。开后，在追问改写、回答生成、条件核对分别展示接收方与该次完整发送文本，然后由用户确认；鉴权密钥仅放在请求头，不包含在预览正文。

预览采用当前会话中的执行结果缓存：确认并完成追问改写后，后续查看回答预览不会重复发送同一个改写请求。确认许可匹配精确文本摘要及本轮范围；文档、服务、历史设置、检索方式、核对选项、证据上限或已有对话改变时取消待请求。每次真实请求仍经过 ModelSession 的文档禁止和接收方许可检查。

取消只能阻止后续未发出的请求，不能撤回已完成的历史改写或回答。中间内容只在当前服务器会话内存里，完成、取消或设置失效时丢弃执行缓存；没有浏览器端离线保证或企业级防泄漏能力。

## 三轮实际验证

使用四道已知问题开发回归题，各服务三轮，并交替运行顺序。修正前和修正后的实验单独保留，不混算。修正后混元完成 12/12 题次；DeepSeek 完成 8/12，三次延期遗漏批准与一次长文遗漏资产管理员审核被核对拦截。各服务 33 次请求均正常返回，无核对格式异常。被拦截意味着暂不当作可靠答案显示，不代表任务完成。

开发者借助 AI 逐题查看被拦截草稿与原文，四次拦截均有对应条件。不是独立人工标注；未看到误报不代表误报率为零。小范围重复题也不能代表真实用户准确率。

修正后单题处理耗时中位数混元 4.175 秒、DeepSeek 2.229 秒，含前置问答和核对；没有同代码同条件的不开核对线上对照，不能定量宣称核对造成多少额外延迟。预览等待时间不算模型处理时间。

原实验曾把条件拦截算进“引用失败”，后续已拆分报告分类；原 JSON 不覆盖，`reporting-corrected` 保存有原始文件摘要的派生报告，只修统计分类、不改回答、预设分数或请求记录。原实验的代码指纹属于当时版本，评测后修正报告显示不冒充重新跑模型。

## 主要验收

- 引用核验通过但遗漏审批的回答：核对指出有原文依据的缺口，状态为未核验，不展示拟回答为可靠答案。
- 核对编造引用、来源编号无效或结构异常：拒绝核对结果，不静默放行。
- 禁止模型发送：三个阶段都受相同的调用层检查；仅检索不触发模型。
- 开启预览：确认前零请求；确认文本与实际发送文本一致；前序请求不因重跑页面而重复。
- 发送设置改变：取消当前待请求；已发内容不可撤回。
- 模型对照：证据上限、核对设置、数据集、代码和题目顺序必须一致。
